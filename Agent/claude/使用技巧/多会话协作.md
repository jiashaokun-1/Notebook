这是一个经典的**多会话协作**问题，核心挑战是：会话之间默认是隔离的，上下文不自动共享。以下是几种可靠的模式：

---

## 模式一：文件作为"共享内存"（最简单）

**会话 A：制定计划**
```
用 Write 工具把计划写入 plan.md，包含：
- 目标和背景
- 分步任务列表（含验收标准）
- 当前状态（pending / done / failed）
```

**会话 B：执行**
```
开头说：「请先读取 plan.md，然后按步骤执行」
执行完每步后更新 plan.md 中的状态
```

**会话 A：验证**
```
读取更新后的 plan.md + git diff 查看实际变更
```

---

## 模式二：Project Memory（本项目已支持）

本项目有 `/Users/sky/.claude/projects/.../memory/` 系统，`MEMORY.md` 会**自动注入每个新会话**。

**会话 A：**
```
让 Claude 把计划核心决策存入 project memory：
「记住这个计划：目标是X，关键约束是Y，需要会话B完成Z步骤」
```

**会话 B：**
- 新会话启动时 `MEMORY.md` 自动加载
- 说：「根据 memory 中的计划，执行 Z 步骤」

**会话 A：**
- 检查 memory 中 B 更新的状态 + 读文件验证

---

## 模式三：Git 分支作为隔离载体（最严格）

```bash
# 会话 A：
# 1. 创建 feature branch + 写 plan.md 并 commit
git checkout -b feature/task-x
# 2. 在 plan.md 里写清 context、steps、expected outputs

# 会话 B：
git checkout feature/task-x   # 切到该分支
# 读 plan.md → 执行 → commit

# 会话 A：
git diff main...feature/task-x  # 审查所有变更
git log feature/task-x          # 查看 B 的 commit 记录
```

---

## 模式四：RemoteTrigger / Schedule（异步触发）

用 `schedule` skill 让会话 A 调度一个 **remote agent** 在后台执行，完成后通知：

```
/schedule 「立即执行：读取 plan.md 并完成所有 pending 步骤，完成后更新状态」
```

---

## 推荐组合（适合这个项目）

| 场景 | 推荐 |
|------|------|
| 简单任务 | plan.md 文件 + 会话 B 直接读取 |
| 需要持久化背景知识 | Project Memory |
| 需要代码隔离/回滚 | Git worktree + plan.md |
| 长期自动化任务 | RemoteTrigger / Schedule |

最关键的原则：**上下文必须外化到文件或 memory 中**——会话间没有隐式共享，所有信息必须显式持久化。
